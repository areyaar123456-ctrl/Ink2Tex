# Model compatibility, artifacts and limitations

Audit date: **2026-11-14**. Immutable artifact URLs, exact sizes and upstream SHA-256 values are in `app/src/main/assets/models.json`. Readable upstream model cards and API responses were saved under `docs/audit/` so identity claims can be checked. Model weights are intentionally not included in the APK or source archive.

## Implemented family: OvisOCR2

- Official model: [ATH-MaaS/OvisOCR2](https://huggingface.co/ATH-MaaS/OvisOCR2), revision `cbdede82e048659b83310476ff807da825f8fe78`, Apache-2.0. Qwen3.5-0.8B vision-language architecture. A page is one input; prose and equations are transcribed together.
- Maintained community conversion: [MDfox/OvisOCR2-GGUF-SOTA-20260823](https://huggingface.co/MDfox/OvisOCR2-GGUF-SOTA-20260823), pinned at `dfe9304de35b13527bf899e2229699224861bb6d`. This is **not an official ATH-MaaS GGUF release**. Its card documents end-to-end conversion evaluation; those upstream scores are not Ink2TeX or Moto Pad benchmarks.
- Quality: Q8_0 language weights **811,843,520 bytes**, plus matching BF16 vision projector **207,346,336 bytes**. Installed payload **1,019,189,856 bytes**.
- Compact: Q6_K language weights **629,744,064 bytes**, plus the same BF16 projector. Installed payload **837,090,400 bytes**. Each installation owns its projector copy so deletion and integrity checking remain independent.
- The GGUF language file includes the tokenizer. `libmtmd` applies Qwen3.5 image preprocessing and produces visual embeddings. The application supplies the upstream full-document transcription prompt and its non-thinking chat template, then uses greedy decoding.
- Runtime: vendored [llama.cpp](https://github.com/ggml-org/llama.cpp/tree/32bdc3a89e6528d3e419024c833c5dabf32c7541), exact commit `32bdc3a89e6528d3e419024c833c5dabf32c7541`; linked into a packaged JNI library. CPU only, ARMv8 baseline, no server, no Python, no downloadable code, no custom upstream patch. C++ exceptions are translated into Kotlin failures. Default context 8192, generation limit 2048, image token budget 1600, up to four CPU threads. The token limit is reported as an incomplete result, not silently accepted as complete.
- Verification: Q8_0 plus BF16 projector passed the shared C++ core on a printed smoke image on the Linux host. A scanned handwritten proof evaluation is recorded separately. Android installation always repeats validation locally before writing the readiness marker. Q6_K has its own on-device validation gate. Compilation for ARM64 is not evidence of Moto Pad latency or accuracy.
- Memory: **unmeasured on the Moto Pad**. The 3 GiB free-memory admission threshold is a conservative software budget, not an empirical requirement or a RAM benchmark. Only one native model is loaded. Page inputs have a four-megapixel Java-side budget and a 1600-token vision budget. Fine or dense handwriting can lose detail at the vision resize; use smaller snips when necessary.
- The model is not a handwriting correctness oracle. Preserve the original image, review all symbols, and do not infer accuracy from successful KaTeX rendering. The app performs no algebraic repair or reasoning completion. It only normalizes `\(...\)` / `\[...\]` into dollar delimiters.

## Installation protocol

The bundled catalogue is trusted application data. Model sources use HTTPS URLs pinned to immutable Hugging Face revisions. File names are constrained to a flat private model directory. Download capacity is checked with a 256 MiB reserve. Transfer progress uses known manifest byte counts; Range / If-Range / ETag resume responses are checked. A source that ignores Range is restarted safely. Oversized, undersized or hash-mismatched payloads cannot be installed. Native code is packaged at build time.

Every component must pass SHA-256. A small local image-to-text inference must also match the smoke image's identifying text without truncation. Only then is `ready.json` atomically committed with the exact component hash fingerprint. Cancellation leaves resumable partial data and no readiness marker. Download errors are displayed. Tap Resume/Download to retry failed transfers. File integrity is rechecked during installation, not by rehashing gigabytes on every UI frame. The catalogue updates with app releases; arbitrary remote manifests are not accepted.
