# Engineering map

One Android application Gradle module contains separate Kotlin packages for the core boundaries. A full vendored native runtime makes the source archive buildable without an unpinned Git checkout or git submodule fetch. Extracting Gradle library modules is future maintenance work, not a runtime dependency.

- `capture`: user-consented projection, single virtual display, a capture thread and private ImageReader ownership, foreground service lifecycle, native Android overlay windows and Quick Settings tile.
- `crop`: frozen-image coordinate system independent of view transform, rectangular corner handles and movement, two-finger pan/pinch, freeform mask and bounded full-resolution crop decoding.
- `preprocessing`: SAF import, direct PDF section rasterization and region-decoded overlapping image tiles. Ordinary images up to 4096×4096 are one model input, sampled only to meet the four-megapixel Java budget; mtmd applies the model's own token budget after that.
- `ocr`: common suspend interface, progress/diagnostics StateFlow, model routing and queue workers. `LocalOcrEngine` owns a single native executor and an operation/session mutex. Cancellation marks a native atomic flag. The executor retains ownership until native code returns; unloading is serialized and finally cleanup is noncancellable. Native vision preprocessing/encoding is not instantaneously interruptible. JNI startup/linkage failures settle the caller; cancelling a worker waiting for the session lock does not cancel its owner. Native atomics expose the active phase and real generated token count; workers relay these with monotonic elapsed time.
- `app/src/main/cpp`: small JNI bridge and the same portable C++ core used by the host evaluation executable. Model-specific prompting is explicitly restricted to Qwen3.5 OCR. No generic “every GGUF works” loader is exposed. Packaged shared CPU backend variants are selected from the trusted app native-library directory using upstream CPU feature probes. BF16 vision tensors are expanded losslessly into a private float32 cache to avoid the scalar ARM BF16 dot-product path. Only an exactly uniform shared corner-color border is trimmed for inference; the stored source stays unchanged and every differently colored pixel is retained.
- `modelmanager`: immutable catalogue, byte/size/hash rules, app-private staging, ETag/Range resume and WorkManager download state. Readiness follows a validation inference and atomic fingerprint marker. Installation validation and OCR acquire the same native session lock.
- `storage`: Room documents and source image paths, DataStore preferences. Multiple proof documents may reference an image; deleting one document removes a physical image only after checking remaining references. Models and capture data are excluded from backup by disabling application backup.
- `stitching`: exact-text boundary merging plus a standalone conservative pixel-overlap helper. The pixel helper is not wired into the active workflow or validated on captured Nebo pages; guided scanning sequences the original images. Defaults preserve all text. Deduplication is an explicit user action and requires at least three identical lines spanning at least 80 characters. Fuzzy semantic deduplication is deliberately absent because it could alter a proof.
- `export`: exact Markdown export, basic TeX wrapping, private temporary shares, local HTML/KaTeX preview and Android's Print framework for PDF. Markdown math is protected from Markdown emphasis parsing. Raw model HTML is escaped, URLs are sanitized, and WebView allows only intercepted bundled resources with no JavaScript bridge.
- `ui`: AndroidViewModel/StateFlow, Compose tablet navigation, home/model/history/settings/diagnostics/editor, independent comparison results and guided proof capture.

## Failure and resource boundaries

Only one inference/validation session holds a loaded native model. No installed model is auto-loaded at startup. Model mmap/native allocations and vision encoding are bounded but **not isolated in a separate process**; a native runtime bug can still terminate the app process. A separate inference process is desirable before a production release. Worker and document state preserve source images for retry. Android can terminate the projection service; it is never restarted using stale consent.

No confidence scores, GPU throughput or memory peaks are invented. Diagnostics expose actual wall-clock timings, token counts, Java/native heap allocation and system available RAM. The three-gigabyte model admission threshold is a policy, not a measurement. Job quotas, OEM background restrictions, foreground-service declarations and sustained thermals need device validation.

## PDF imports

The importer keeps ordinary pages in one image at up to 1800 pixels on the longest edge. For pages more than twice as tall as they are wide, it scales by width up to 1120 pixels across and 2.5 pixels per PDF point. It renders a bounded probe near the next cut and selects a cut in a full-width white gap when possible. When no gap is available it retains 128 pixels of overlap. Conversion receives ordered lossless PNG sections in one history document and uses full OCR detail. Source limits are 500 pages and 128 million planned page pixels per import. PNGs are private and removed if an import fails before its history record commits.

## Equation layout and timing in 0.1.2

`format/MathLayout` promotes math-only lines from inline to display delimiters without changing their contents and skips fenced/indented code. OCR stores this formatting for new results; HTML previews also apply it to existing results without editing saved source. KaTeX remains locally bundled with untrusted content disabled. The faster-scan preference is read once per worker; native processor bounds are set at model load and included in active-model identity. Validation remains full detail. Native monotonic timers distinguish preprocessing, combined vision/prompt evaluation and output generation; they are read on the same executor as inference.

## Handwriting examples

The app saves the two latest confirmed examples in private DataStore, with exact corrected text and links to existing private source images. Snapshot text is preserved until explicitly saved again. Deletion of the teaching note or its original clears its example. Eligible input is one short raster, at most 1600 × 800 and 400 characters. Examples are resized for inference, excluded from a scan of their own source, and omitted during installation validation and benchmarks. JNI sends each bitmap and literal UTF-8 transcription as a prior Qwen chat turn. The trusted template controls chat tokens and the demonstration text is tokenized without interpreting special markers. The Android multimodal log callback suppresses private prompt text.

## On-device weight training

Room v2 adds reviewed labels keyed by owner note and image path. No image copies are written by review. Training excludes evaluation notes and exact duplicate images, and uses the latest twelve eligible training images and up to three marked evaluation images. Validation is a bounded pilot on the selected set. Character edit counts measure transcription differences and cannot establish mathematical correctness.

The trainer uses teacher-forced, checked OCR tokens including the stop token. Masked NextN outputs supply the final normalized decoder states. Native code caches these along with the base target score and the eight strongest competing token scores. Six shuffled passes fit a regularized sparse delta to at most 192 output rows. The base GGUF, vision weights and intermediate decoder weights stay frozen. Every batch fits a fresh candidate from its selected labels, and ordinary inference adds the learned output scores while reading one target image. No Python, model downloads, network service or GPU is needed for this Android training path.

Training and OCR share the same native session lock. A candidate is evaluated on full generated outputs against the stored active checkpoint or the stock model. Ties, empty output, truncation and per-image regressions cannot promote it. Checkpoints are local to a base model directory and are replaced by a same-directory rename only after validation. Cancellation and failure discard staged weights. Bad checkpoint data is reported and OCR falls back to stock. Training labels are private until the user explicitly exports the dataset.

## Guided batches and checkpoints

Room v3 adds per-original OCR drafts, provenance for new crops, and a persistent training run ledger. Existing rows migrate intact. The planner groups note sources, linked crop origins and exact image hashes. It keeps reserved images out of fitting and excludes previously used training groups from evaluation. Exact hashes and recorded origins do not identify every near-duplicate or older crop. Use separately handwritten notes for a meaningful evaluation set.

The first batch reserves a separate note automatically unless explicit evaluation labels are available. It pins the evaluation images. New revisions are prioritized per base model, with up to two replay images and twelve total training images per batch. The worker verifies the batch fingerprint before it starts. Candidate fitting clones the active sparse head, so cancellation leaves active parameters untouched. A run records full generated-output comparisons with current weights on the same images, including text and formula edit counts and measured recognition times. Better text does not compensate for a worse math score. An accepted candidate preserves the preceding checkpoint, which can be restored in Training.

For long evaluation images, the worker finds blank horizontal gaps with a bounded region decoder. It visits each non-overlapping crop in reading order and feeds it to both weights. It joins each set of results in that order and retains repeated lines. Empty or truncated output in either set prevents promotion and appears in the scorecard with its snip number. Review can also save the crops as a separate note for per-image labeling. Crop ancestry keeps related notes within a single training or evaluation group.

Drafts are local starting points for review. Unchecked output never becomes a label. Existing multi-image notes without per-image drafts can be rerun or reviewed with manually supplied source.
