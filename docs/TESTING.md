# Test evidence and device acceptance plan

Evidence is generated by the actual commands in this workspace. This file distinguishes host/unit evidence from Android device evidence. No Android device or emulator was attached (`adb devices -l` returned an empty device list).

## Automated checks

**Executed: 38 tests passed, 0 failures, 0 skips; Android lint has 0 errors and 40 warnings; app and instrumentation APKs compiled.** Device instrumentation was not executed.

Final build/test/lint results are recorded in `docs/testing/build-results.txt` and the delivered reports. The project contains JVM logic tests, Robolectric Android storage/cropping/integrity tests, and device instrumentation tests that require an installed model for real JNI recognition.

The tests cover:

- Reading-order tile coverage and bounded sizes, invalid budgets, and keeping ordinary screenshots as a coherent page.
- Retaining deliberately incorrect mathematics, inequality direction and divisibility notation.
- Preserving repeated lines by default; exact substantial boundary deduplication only when explicitly selected; preserving changed signs.
- Delimiter normalization without algebraic changes.
- TeX prose escaping while preserving formulas, and HTML/remote-resource defenses in previews.
- Immutable artifact URLs, complete text+vision component sets and upstream SHA-256 format.
- Refusal to mark files Ready without validation and detection of payload corruption by hash.
- Full-coordinate rectangular crops, white-background freeform masking, and shared-image reference safety when deleting proof sections.

Additional 0.1.1 regressions cover faint-pixel/ruled-line retention during conservative border trimming, actual native stage/token labels and completion of a missing-JNI-library startup failure. The native fixture executable also passed exact BF16-to-F32 bit checks (including signed zero, subnormal, infinity and NaN), unchanged F32 tensors/metadata/original downloads, cache reuse, cancellation cleanup and retry; see `docs/testing/cpu-projector-test.txt`. This fixture is not an OCR accuracy or speed benchmark.

APK verification confirms all seven ARM CPU backend modules and their required libraries are packaged, all native LOAD segments have 16 KB alignment, versionCode is 4, and the original signing certificate is retained. Runtime CPU dispatch on the tablet and the performance effect of the new vision cache have not been measured.

0.1.2 adds layout regressions for unchanged expression bodies, deliberately incorrect mathematics, inline spans, escaped dollar signs, existing display blocks, code fences/indentation and old-result previews. A Robolectric test verifies the speed preference survives settings-object recreation and can restore full detail. `display-math-test.txt` records the bundled KaTeX host JavaScript check for above/below display limits versus inline side limits. Android instrumentation now requests both profiles and checks genuine smoke transcription and native timing values; it was compiled, not executed.

These tests do not establish Android consent UI behavior or handwriting accuracy.

## PDF import regression

0.1.3 adds five tests for readable raster width, complete ordered row coverage, white-gap cuts, overlapping fallback, a narrow-page threshold edge case, and unchanged landscape raster width. The compiled Android instrumentation test creates a synthetic tall PDF and checks its first and last ink marks through Android's renderer. A separate host-side geometry check on a tall Nebo export located five sections and four white-gap boundaries at the higher resolution. The PDF and its content are kept out of the public repository and bundle. These checks verify raster planning. A host run with OvisOCR2 Compact on a separate high-resolution crop of three lines retained the exponents but misread two of the three divisor symbols. That sample failed strict fidelity acceptance. The host run gives no tablet timing or full-PDF accuracy measurement.

## Native recognition evidence

`docs/testing/host-smoke-output.md` is genuine model output from OvisOCR2 Q8_0 + BF16 projector, generated by the same C++ core that JNI calls. It reads the printed smoke image as a product name, prose and inline mathematics. `host-smoke.log` contains the actual runtime trace and wall-clock time. This verifies image embeddings, tokenization and decoding, not a math-specific mock or separately running inference server.

`handwritten-sample.jpg` is a public scanned topology solution, attributed in `sample-origin.txt`. `handwritten-evaluation.png` is a bounded-size copy used for engineering evaluation. The evaluation uses one full page, with printed English/math and handwritten English/math together. `host-handwriting-output.md` and its log preserve the actual output. Original prompt snapshots are retained. This is one engineering sample, not a validated accuracy dataset.

The long handwritten evaluation was temporarily paused while the Android compiler ran; its wall-clock timing is therefore unsuitable as a performance benchmark. Host CPU timings must never be presented as Moto Pad timings. See `docs/testing/handwriting-review.md` for the actual fidelity observations after the run completes.

## Required target-device checks

All entries below remain **pending on the target device** unless a final evidence file explicitly records otherwise. Code paths and host/unit tests are supporting evidence, not substitutes for these checks.

| # | Device acceptance scenario | Procedure / pass condition |
|---|---|---|
| 1 | First-launch permissions | Clean install; deny and then grant notifications, overlay and projection separately; import remains available after denial. |
| 2 | Start / stop | Start from visible activity; choose screen/app; see persistent indicators; Stop removes overlay and ends projection. New start asks again. |
| 3 | Panel over Nebo | Write using stylus while bubble is visible; expand/collapse, drag, edge-snap and pause/resume without obstructing ordinary writing. |
| 4 | Screenshot conversion | Screenshot excludes scanner controls; real installed model yields mixed prose/formulas and opens review. |
| 5 | Stylus rectangle | Select, move, resize corners, pinch and pan on the frozen capture. Crop contains the intended original pixels. |
| 6 | Multiple captures | Repeat at least 20 scans and verify correct images/results with no retained projection objects after Stop. |
| 7 | Mixed handwritten mathematics | Use real Nebo proofs with fractions, indices, inequalities, congruences and Greek symbols; compare each character and order to the original. Include intentionally incorrect steps. |
| 8 | Long proof / large import | Import a large image and multipage PDF; guide scrolling captures; inspect every tile/section boundary and confirm bounded memory. |
| 9 | Rotation | Rotate Nebo during projection and rotate the crop/editor activity. Display resizes without a second `createVirtualDisplay`; selection and source edits survive. |
| 10 | Revocation / lock | Stop using system projection chip or lock the tablet. Resources and bubble disappear; fresh consent is required. |
| 11 | Multiple models | Install Q8 and Q6; validate both, switch, compare and delete one. Only one model is resident. Additional families remain unavailable. |
| 12 | Corrupt transfer | Interrupt and corrupt a staging payload on a test build; checksum prevents Ready and offers retry. |
| 13 | Insufficient storage | Fill a test device below the storage reserve; download is rejected without destroying existing model/source data. |
| 14 | Cancellation | Cancel while loading, encoding and generating; source remains; no JNI ownership race; another conversion can run. Encoding may finish its current native stage before cleanup. |
| 15 | Background / reopen | Queue work, background and reopen; work state and history persist. Record any Android 16 job-quota delay. |
| 16 | Clipboard / exports | Compare copied and `.md` bytes to editor source; open `.tex` in a TeX tool; print a rendered PDF and inspect equations. Share and batch ZIP contain chosen text. |
| 17 | Repeated OCR / memory | Run instrumented repeated local inference and capture RSS/peak heap/thermal behavior on the actual Dimensity 8300. No crash or unbounded growth. |
| 18 | Airplane mode | After validation, disable all networking and rerun screenshots/imports, rendering, copying and exports. No network request is required for recognition. |

## Commands on a device

Install a built APK, download a model through Model Store, then run `./gradlew :app:connectedDebugAndroidTest`. The model-dependent instrumentation tests use `Assume` to skip when no model has been installed; a skip is not a pass. For airplane-mode acceptance, run again with networking disabled. Nebo and projection/stylus tests require interactive consent and actual tablet behavior; do not bypass consent using accessibility automation.
